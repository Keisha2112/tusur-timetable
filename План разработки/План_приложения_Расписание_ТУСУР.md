# План Android-приложения «Расписание ТУСУР»

**Статус:** итоговый план, согласованные требования зафиксированы  
**Дата:** 27.10.2026  
**Тип проекта:** личное приложение для себя и друзей  
**Платформа:** Android  
**Распространение:** подписанный APK для ручной установки

---

## 1. Цель

Сделать простое и надёжное Android-приложение, которое показывает расписание занятий выбранной группы ТУСУР.

Основной сценарий:

1. Пользователь устанавливает приложение и при первом запуске выбирает факультет и группу.
2. Выбор сохраняется.
3. При следующих запусках сразу открывается расписание этой группы на текущую неделю.
4. Чтобы сменить группу, пользователь заходит в настройки, выбирает другой факультет и группу, после чего расписание перезагружается.

Приложение неофициальное, не требует авторизации и не собирает персональные данные.

## 3. Исследование источника данных

Сайт: **https://timetable.tusur.ru**

Публичного API у сайта нет. Это серверное Rails-приложение с HTML-страницами и официальным экспортом в iCal.

### Используемые адреса

| URL | Назначение |
|---|---|
| `/faculties` | Список факультетов, звонковое расписание, информация о семестре |
| `/faculties/{faculty}` | Группы факультета, разбитые по курсам |
| `/faculties/{faculty}/groups/{group}` | Страница группы: список недель и HTML-таблица занятий |
| `/faculties/{faculty}/groups/{group}.ics` | Все опубликованные занятия группы в формате iCal |

Примеры:

- `https://timetable.tusur.ru/faculties`
- `https://timetable.tusur.ru/faculties/fb`
- `https://timetable.tusur.ru/faculties/fb/groups/714-2`
- `https://timetable.tusur.ru/faculties/fb/groups/714-2.ics`

### Важные особенности сайта

1. В списке недель класс `current-week` обозначает реальную текущую неделю, а класс `current` — всего лишь выбранную в запросе. Их нельзя путать.
2. HTML-таблица занятий свёрстана с ошибками: встречаются незакрытые и дублирующиеся `<tr>`. Разбор такой таблицы возможен, но хрупок.
3. Экспорт `.ics` содержит полное название дисциплины, тип занятия, преподавателей и аудитории.
4. Количество занятий в `.ics` совпадает с HTML. Проверено:
   - группа 714-2 — 172 события, за неделю 9 — 23 занятия;
   - группа 716-1 — 18 занятий за неделю 9.
5. В `.ics` нет `UID`, `RRULE`, `STATUS`, поэтому стабильный идентификатор занятия формируется из даты, времени и названия.
6. Расписание публикуется не на весь семестр. На 27.10.2026 у группы 714-2 заполнены недели 1–9, а недели 10–23 присутствуют в списке, но занятий в них пока нет.
7. Сайт отвечает медленно: примерно 1–3,5 секунды на страницу.
8. Сайт поддерживает `ETag` и возвращает `304 Not Modified`, если данные не изменились.
9. Часовой пояс расписания — `Asia/Novosibirsk` (UTC+7).
10. В `robots.txt` запретов нет: все правила закомментированы.

### Главное техническое решение

Занятия берём из `.ics`, а из HTML — только каталог факультетов/групп и список недель.

Почему:

- один лёгкий запрос вместо разбора большой и битой HTML-таблицы;
- стабильный стандартный формат;
- полные названия дисциплин;
- меньше нагрузка на сайт;
- проще тестировать.

Ограничение: в `.ics` нет примечаний и флагов отмены. Если они понадобятся, это будет отдельный этап с разбором HTML.

### Особенности minSdk 23

`java.time` появился только в API 26, поэтому обязательно включаем core library desugaring:

- `minSdk = 23`;
- `isCoreLibraryDesugaringEnabled = true`;
- зависимость `desugar_jdk_libs`;
- используем `LocalDate`, `LocalTime`, `ZonedDateTime`, `DateTimeFormatter` без ограничений.

Это увеличивает APK примерно на 1–2 МБ, но сохраняет удобную работу с датами.

Compose, Room, OkHttp, Jsoup и biweekly поддерживают API 23. Отдельно проверяем приложение на эмуляторе Android 6.0 и, желательно, на реальном старом устройстве.

## 5. Архитектура

Три слоя:

```text
UI (Compose)
  ↓
ViewModel (StateFlow)
  ↓
Repository
  ├── Network (OkHttp + парсеры)
  └── Cache (Room + DataStore)
```

### Структура пакетов

```text
app/
  data/
    network/      TusurClient, Urls, UserAgent
    parser/       CatalogParser, WeekListParser, IcsParser
    local/        AppDatabase, CatalogDao, ScheduleCacheDao
    repository/   CatalogRepository, ScheduleRepository, SettingsRepository
  domain/
    model/        Faculty, Group, Week, Lesson, DaySchedule, GroupSchedule
  ui/
    onboarding/   выбор факультета и группы
    schedule/     главный экран
    settings/     настройки
    components/   карточка занятия, недельная панель, пустые состояния
    theme/
  App.kt
  MainActivity.kt
  AppContainer.kt
```

### Поток данных

**Запуск приложения:**

1. Читаем выбранную группу из DataStore.
2. Если выбора нет — открываем онбординг.
3. Если выбор есть — загружаем кэш расписания и сразу показываем текущую неделю.
4. В фоне проверяем, не устарел ли кэш, и при необходимости обновляем.

**Обновление расписания:**

1. Параллельно запрашиваем `.ics` и, если список недель устарел, страницу группы.
2. Разбираем ответы.
3. Раскладываем занятия по неделям.
4. Сохраняем результат в Room.
5. Обновляем UI.

**Смена группы:**

1. Пользователь выбирает новый факультет и группу.
2. Сохраняем выбор в DataStore.
3. Сбрасываем выбранную неделю на текущую.
4. Загружаем расписание новой группы.
5. Возвращаемся на главный экран.

## 7. Парсинг

### 7.1. Каталог факультетов

Страница `/faculties`:

- `ul.faculties li a` → код факультета из `href`, название из текста.

Кэш — 7 дней.

### 7.2. Группы факультета

Страница `/faculties/{faculty}`:

- `h2` → курс;
- следующие за ним `ul.list-inline li a` → название и slug группы.

Кэш — 7 дней.

Если группа исчезла с сайта, при обновлении показываем сообщение «Группа не найдена, выберите другую».

### 7.3. Список недель

Берём только `ul.weeks li` со страницы группы:

- `week_id` из ссылки;
- номер недели;
- дату начала вида `с 31 августа 2026`;
- тип недели из классов `day_color_theoretical`, `day_color_exam_session`, `day_color_weekend`;
- текущую неделю — по классу `current-week`, а не `current`.

Для экономии памяти можно вырезать из HTML только фрагмент `ul.weeks` и передавать в Jsoup его.

Кэш — 7 дней.

### 7.4. Занятия из `.ics`

Используем biweekly.

Из каждого события берём:

- `DTSTART` и `DTEND` → дата и время в `Asia/Novosibirsk`;
- `SUMMARY` → полное название дисциплины;
- `DESCRIPTION` → первый элемент тип занятия, остальные — преподаватели;
- `LOCATION` → аудитории через запятую.

Нужно корректно обрабатывать:

- переносы строк в `.ics`;
- экранированные запятые;
- пустые `LOCATION` и `DESCRIPTION`;
- несколько преподавателей и аудиторий;
- события без названия;
- события вне списка недель.

### 7.5. Типы занятий

Маппинг:

- «Лекция» → `LECTURE`;
- «Практика» → `PRACTICE`;
- «Лабораторная работа» → `LABORATORY`;
- «Научно-исследовательская работа» → `RESEARCH`;
- «Консультация» → `CONSULTATION`;
- «Экзамен» → `EXAM`;
- «Зачёт» / «Зачет» → `CREDIT`;
- всё остальное → `OTHER`, исходный текст сохраняем в `rawType`.

### 7.6. Раскладка по неделям

Для каждого события:

1. Определяем дату в часовом поясе `Asia/Novosibirsk`.
2. Ищем неделю, в диапазон которой попадает дата.
3. Если неделя не найдена, создаём синтетическую неделю с датой начала.
4. Сортируем занятия по времени начала, затем по названию.

Дни показываем с понедельника по воскресенье. Воскресенье отображаем только если там есть занятия.

### 7.7. Номер пары

Номер пары определяем по времени начала из звонкового расписания.

Стандартные пары:

| Пара | Время |
|---|---|
| 1 | 08:50–10:25 |
| 2 | 10:40–12:15 |
| 3 | 13:15–14:50 |
| 4 | 15:00–16:35 |
| 5 | 16:45–18:20 |
| 6 | 18:30–20:05 |
| 7 | 20:15–21:50 |

Если время нестандартное, номер пары не показываем — только время.

### 7.8. Текущая неделя и «сегодня»

- «Сегодня» определяем по часовому поясу `Asia/Novosibirsk`, а не по часовому поясу телефона.
- Текущую неделю берём по `current-week`, но дополнительно проверяем по датам.
- Если сервер и расчёт расходятся, приоритет у расчёта по датам.
- Если сегодня воскресенье или праздник, показываем текущую неделю с пустым состоянием, а не перескакиваем самовольно.

### 7.9. HTML-таблица занятий

В MVP не парсится. Причина — битая разметка и отсутствие необходимости: `.ics` даёт все основные поля.

Если позже понадобятся примечания, отмены или статусы дней, добавляем отдельный tolerant-парсер:
- извлекаем `td` в порядке документа;
- группируем по дню;
- покрываем тестами все варианты таблиц.

Нижний лист со всеми неделями:

- Все тексты на русском.
- Тексты вынесены в `strings.xml`.

- Списки преподавателей: первые два + «и ещё N», полностью — в деталях.
- Если аудитории или преподаватели не указаны, строки скрываются.
- Кнопки и карточки имеют достаточную область нажатия.
- Контраст текста проверен для светлой и тёмной темы.
- Цвет не является единственным носителем смысла: тип занятия всегда подписан.

## 9. Хранение, кэш и обновление

### DataStore

Хранит:

- код факультета;
- название факультета;
- slug группы;
- название группы;
- версию схемы настроек.

### Room

Таблицы:

- `faculties` — код, название, время обновления;
- `groups` — факультет, slug, название, курс, время обновления;
- `schedule_cache` — группа, JSON расписания, ETag для `.ics`, ETag для HTML, время обновления.

Расписание хранится как сериализованный `GroupSchedule` в JSON. Это удобно: при изменении парсера не нужно менять схему базы.

### TTL

| Данные | Срок |
|---|---|
| Каталог факультетов | 7 дней |
| Группы факультета | 7 дней |
| Список недель | 7 дней |
| Расписание `.ics` | 15 минут для текущей недели, 6 часов для остальных |

### Обновление

- При старте: сначала кэш, потом фоновое обновление.
- Pull-to-refresh: принудительное обновление.
- ETag: хранить и отправлять `If-None-Match`. При `304` обновлять только время проверки.
- Не запускать параллельные одинаковые запросы: если обновление уже идёт, второй запрос ждёт его результат.
- Таймаут сети — 30 секунд.
- User-Agent с названием и версией приложения.
- Без частого polling. Один запрос `.ics` на группу при обновлении.

### Офлайн

- Если сеть недоступна и есть кэш — показываем кэш и баннер.
- Если кэша нет — экран ошибки с кнопкой «Повторить».
- Время последнего успешного обновления показываем в настройках или на главном экране.

## 10. Ошибки и крайние случаи

| Ситуация | Поведение |
|---|---|
| Нет интернета, есть кэш | Показать кэш + баннер |
| Нет интернета, нет кэша | Экран ошибки + «Повторить» |
| `404` по группе | «Группа не найдена», кнопка в настройки |
| `5xx` или таймаут | Повторить, кэш не затирать |
| Пустой `.ics` | «Расписание не опубликовано» — это не ошибка |
| Ошибка парсинга | Оставить старый кэш, показать «Не удалось обновить» |
| Несколько занятий в одной ячейке | Показать несколько карточек |
| Событие вне списка недель | Синтетическая неделя |
| Неизвестный тип занятия | Показать исходный текст |
| Нет аудитории | Скрыть строку |
| Нет преподавателей | Скрыть строку |
| Смена часового пояса на телефоне | Расписание не меняется, используется `Asia/Novosibirsk` |

## 13. Риски и меры

| Риск | Мера |
|---|---|
| Сайт изменит вёрстку или формат `.ics` | Парсеры изолированы, есть фикстуры и тесты; при поломке показываем кэш |

## 14. Сборка и распространение

### Сборка

- `release` с R8 и `shrinkResources`.
- Универсальный APK без ABI-разделения.
- `versionCode = 1`, `versionName = "1.0.0"`.
- Подпись личным keystore.
- Keystore и `keystore.properties` не коммитить.
- Проверить APK через `apksigner verify`.

### README

В README приложить:

- описание приложения;
- скриншоты;
- инструкцию по установке;
- SHA-256 APK;
- требования (Android 6.0+);
- дисклеймер о неофициальности;
- ссылку на источник данных;
- инструкцию по обновлению;
- предупреждение, что при удалении приложения настройки теряются.

### Установка

- Android 6–7: «Настройки → Безопасность → Неизвестные источники».
- Android 8+: «Установка неизвестных приложений» для файлового менеджера или браузера.
- Если Play Protect предупреждает, выбрать «Установить всё равно».
- Обновление — установка поверх старой версии с тем же package name и ключом.

### Название и package name

Рабочее название: **«Расписание ТУСУР»**.

Package name не должен выглядеть как официальный пакет ТУСУР. Использовать что-то вроде:

```text
com.<author>.tusur.timetable
```

Иконка — нейтральная календарная, без официального логотипа ТУСУР.

## 17. Итоговое решение

Делаем нативное Android-приложение на Kotlin + Jetpack Compose.

Данные:

- каталог — HTML;
- недели — HTML;
- занятия — `.ics`.

Хранение:

- DataStore — выбор пользователя;
- Room — кэш.

Основной сценарий:

1. Первый запуск → выбор факультета и группы.
2. Далее при каждом запуске → сразу расписание текущей недели.
3. Смена группы → только через настройки.

Ограничения:

- только групповое расписание;
- без уведомлений и виджетов;
- без официальной affiliation;
- APK для ручной установки;
- Android 6.0+.
